Intermediate Operations

Filtering, Mapping, Slicing, Sorting — every operation in depth

filter(Predicate<T> predicate)Stateless · Lazy
Stream<T>
Predicate<T>
O(n)
No

Returns a stream containing only elements that match the given predicate.

Java — filter() 
List<Integer> nums = Arrays.asList(1,2,3,4,5,6);

// Basic filter
List<Integer> evens = nums.stream()
    .filter(n -> n % 2 == 0)
    .collect(Collectors.toList()); // [2, 4, 6]

// Chaining multiple filters (same as Predicate.and())
nums.stream()
    .filter(n -> n % 2 == 0)
    .filter(n -> n > 3)
    .collect(Collectors.toList()); // [4, 6]

// Predicate composition
Predicate<Integer> isEven    = n -> n % 2 == 0;
Predicate<Integer> isPositive = n -> n > 0;
nums.stream().filter(isEven.and(isPositive)).collect(Collectors.toList());

// Real-world: active premium users over 18
users.stream()
    .filter(User::isActive)
    .filter(User::isPremium)
    .filter(u -> u.getAge() >= 18)
    .collect(Collectors.toList());
🎯

Interview Tip

Chaining multiple filter() calls is semantically equivalent to Predicate.and(), but chaining is more readable. JVM fuses them into a single pass. Always place the most selective (fewest matches) filter first.

map(Function<T, R> mapper)Stateless · Lazy
Stream<R>
Function<T,R>
O(n)
No

Transforms each element from type T to type R using the mapping function. One-to-one transformation.

Java — map() 
// String to length
Stream.of("Java","Stream","API")
    .map(String::length)
    .collect(Collectors.toList()); // [4, 6, 3]

// Uppercase with method reference
Stream.of("hello","world").map(String::toUpperCase).collect(Collectors.toList());
// ["HELLO", "WORLD"]

// Entity → DTO transformation (most common real-world use)
List<UserDto> dtos = users.stream()
    .map(u -> new UserDto(u.getId(), u.getName(), u.getEmail()))
    .collect(Collectors.toList());

// mapToInt, mapToLong, mapToDouble — avoid boxing
int totalLen = Stream.of("Java","Streams").mapToInt(String::length).sum(); // 11
flatMap(Function<T, Stream<R>> mapper)Stateless · Lazy
Stream<R>
Function<T,Stream<R>>
O(n×m)
No

Maps + Flattens — maps each element to a stream, then flattens all those streams into one. Key for nested collections.

Java — flatMap() 
// Flatten nested list — the classic flatMap use case
List<List<Integer>> nested = Arrays.asList(
    Arrays.asList(1,2,3),
    Arrays.asList(4,5),
    Arrays.asList(6,7,8)
);
List<Integer> flat = nested.stream()
    .flatMap(Collection::stream)
    .collect(Collectors.toList()); // [1,2,3,4,5,6,7,8]

// Split sentences into words
List<String> sentences = List.of("Hello World","Java Streams");
List<String> words = sentences.stream()
    .flatMap(s -> Arrays.stream(s.split(" ")))
    .collect(Collectors.toList()); // ["Hello","World","Java","Streams"]

// All hobbies across all people
List<String> hobbies = people.stream()
    .flatMap(p -> p.getHobbies().stream())
    .distinct()
    .collect(Collectors.toList());
💡

map() vs flatMap()

map() → one element in, one element out. If mapping function returns a Stream, you get Stream<Stream<T>>.
flatMap() → one element in, zero or more elements out. Flattens nested streams automatically.

distinct(), sorted(), limit(), skip()

Java — Slicing & Sorting 
List<Integer> nums = Arrays.asList(5,3,1,3,4,2,5);

// distinct() — removes duplicates using equals()
nums.stream().distinct().collect(Collectors.toList()); // [5,3,1,4,2]

// sorted() — natural order (requires Comparable)
nums.stream().sorted().collect(Collectors.toList()); // [1,2,3,3,4,5,5]

// sorted(Comparator) — custom order, reverse, then by name
employees.stream()
    .sorted(Comparator.comparing(Employee::getSalary)
        .reversed()
        .thenComparing(Employee::getName))
    .collect(Collectors.toList());

// limit(n) — take first n (enables lazy processing of infinite streams)
Stream.iterate(1, n -> n+1).limit(5).collect(Collectors.toList()); // [1,2,3,4,5]

// skip(n) — discard first n (ideal for pagination)
nums.stream().skip(2).collect(Collectors.toList()); // [1,3,4,2,5]

// Pagination: page 2, pageSize 3
int page=2, size=3;
nums.stream().skip((long)(page-1)*size).limit(size).collect(Collectors.toList());

takeWhile() & dropWhile() — Java 9+

Java 9+ 
List<Integer> ordered = List.of(1,2,3,4,5,1,2);

// takeWhile — take elements WHILE predicate true, stop at first false
ordered.stream().takeWhile(n -> n < 4).collect(Collectors.toList());
// [1,2,3]  stops when 4 is encountered

// dropWhile — drop elements WHILE predicate true, keep rest
ordered.stream().dropWhile(n -> n < 4).collect(Collectors.toList());
// [4,5,1,2]
⚠️

Unlike filter()

takeWhile/dropWhile stop at the first failure point — they don't scan the whole stream. Best used on sorted/ordered streams.

peek(Consumer<T> action)Stateless · Lazy · Debug Only

Performs an action on each element without modifying the stream. Use exclusively for debugging pipeline stages.

Java — peek() for debugging 
List<Integer> result = Stream.of(1,2,3,4,5)
    .peek(n -> System.out.print("pre-filter:"+n+" "))
    .filter(n -> n % 2 == 0)
    .peek(n -> System.out.print("post-filter:"+n+" "))
    .map(n -> n * n)
    .collect(Collectors.toList());
// Output reveals element-by-element lazy execution
🚨

Never Mutate in peek()

Use peek() for debug logging only. Never modify state inside it — in parallel or optimized pipelines, peek may not be called on all elements.
