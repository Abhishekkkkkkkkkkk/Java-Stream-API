Performance Considerations

Boxing costs, lazy evaluation, memory implications, and tuning tips

Java — Performance Anti-patterns vs Optimizations 
// ❌ ANTI-PATTERN 1: Boxing on large numeric work
long sum1 = Stream.iterate(1, n->n+1).limit(10_000_000)
    .mapToLong(Integer::longValue).sum(); // boxes each int!

// ✅ OPTIMIZATION 1: Use primitive stream — up to 8x faster
long sum2 = LongStream.rangeClosed(1, 10_000_000).sum();

// ❌ ANTI-PATTERN 2: map() before filter() — wastes work
list.stream()
    .map(Employee::getName)         // runs on ALL 1000 employees
    .filter(n -> n.startsWith("A")) // then filters
    .collect(Collectors.toList());

// ✅ OPTIMIZATION 2: filter() before map()
list.stream()
    .filter(e -> e.getName().startsWith("A")) // narrows first
    .map(Employee::getName)                   // map runs on fewer
    .collect(Collectors.toList());

// ❌ ANTI-PATTERN 3: sorted() on unbounded stream
Stream.generate(Math::random).sorted().findFirst(); // ❌ hangs forever!

// ✅ OPTIMIZATION 3: limit() before sorted()
Stream.generate(Math::random).limit(1000).sorted().findFirst();

// ❌ ANTI-PATTERN 4: parallel on tiny lists
List.of(1,2,3).parallelStream().map(n->n*2).collect(Collectors.toList());
// Thread overhead >> computation time

// ✅ OPTIMIZATION 4: parallel only for large CPU-heavy work
largeList.parallelStream().map(this::expensiveTransform).collect(Collectors.toList());
