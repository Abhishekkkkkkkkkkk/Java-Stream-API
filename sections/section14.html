Common Mistakes & Pitfalls

The errors that trip up even experienced Java developers

Java — 8 Critical Mistakes to Avoid 
// MISTAKE 1: Reusing a consumed stream → IllegalStateException
Stream<String> s = Stream.of("a","b");
s.forEach(System.out::println);
s.count(); // ❌ IllegalStateException: stream already operated upon
// Fix: use Supplier<Stream<T>> for reusable pipelines

// MISTAKE 2: Modifying source during streaming → ConcurrentModificationException
List<String> list = new ArrayList<>(Arrays.asList("a","b","c"));
list.stream().forEach(e -> list.remove(e)); // ❌
// Fix: collect to new list, then modify original

// MISTAKE 3: No terminal operation — pipeline never executes
list.stream().filter(e -> e.startsWith("a")).map(String::toUpperCase);
// ❌ Nothing printed/returned — no terminal op! Add .collect() or .forEach()

// MISTAKE 4: Using peek() for mutations
list.stream().peek(e -> e.setActive(true)).collect(Collectors.toList());
// ❌ peek is unreliable for side effects — use map() or forEach() instead

// MISTAKE 5: toMap() with duplicate keys
List.of("a","a","b").stream()
    .collect(Collectors.toMap(Function.identity(), String::length)); // ❌ ISE
// Fix: add merge function (v1, v2) -> v1

// MISTAKE 6: forEach() to build a collection (race condition in parallel)
List<Integer> result = new ArrayList<>();
nums.parallelStream().forEach(result::add); // ❌ NOT thread-safe!
// Fix: .collect(Collectors.toList())

// MISTAKE 7: Infinite stream without limit
Stream.iterate(0, n->n+1).collect(Collectors.toList()); // ❌ Infinite loop! OOM
// Fix: add .limit(n) before terminal op

// MISTAKE 8: NullPointerException from null elements
Stream.of("a",null,"b").map(String::toUpperCase).collect(Collectors.toList());
// ❌ NPE on null element!
Stream.of("a",null,"b").filter(Objects::nonNull).map(String::toUpperCase)
    .collect(Collectors.toList()); // ✅
