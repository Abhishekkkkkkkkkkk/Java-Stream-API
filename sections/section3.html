Complete Stream Lifecycle

Source → Intermediate Ops → Terminal Op → Result

Stream Lifecycle
① SOURCE
Collection / Array / File / Generator
→
② INTERMEDIATE OPS
filter, map, sorted… (Lazy, 0 or more)
→
③ TERMINAL OP
collect, reduce, forEach… (Eager)
→
④ RESULT
Value / Collection / Side Effect

Key Rules

  • Streams are single-use — calling a terminal op "closes" the stream. Reusing throws IllegalStateException.
  • Intermediate ops are lazy — they build a pipeline but don't execute until terminal op fires.
  • Terminal ops are eager — they trigger the whole pipeline.
  • Chaining — each intermediate op returns a new stream, enabling method chaining.
Java — Stream Single Use 
Stream<String> stream = Stream.of("a","b","c");
stream.forEach(System.out::println); // ✅ Works
stream.forEach(System.out::println); // ❌ IllegalStateException!

// ✅ Fix: use Supplier for fresh streams
Supplier<Stream<String>> sup = () -> Stream.of("a","b","c");
sup.get().forEach(System.out::println); // ✅
sup.get().forEach(System.out::println); // ✅

Stateless vs Stateful Operations

Type Operations Behavior Parallel Safety
Stateless filter, map, flatMap, peek, mapToInt Each element processed independently ✅ Fully parallel-safe
Stateful sorted, distinct, limit, skip Must see multiple/all elements first ⚠️ Limited parallelism
