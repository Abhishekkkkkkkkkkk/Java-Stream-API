Terminal Operations

Triggering stream execution — collect, reduce, match, find, and more

collect(Collector<T, A, R>)Terminal · Mutable Reduction

The most versatile terminal op — performs mutable reduction into a container like List, Set, Map, or String.

Java — collect() essentials 
Stream<String> names = Stream.of("Alice","Bob","Carol");

// → List
List<String> list = names.collect(Collectors.toList());

// → Set (unordered, no duplicates)
Set<String> set = names.collect(Collectors.toSet());

// → Unmodifiable List (Java 16+ shorthand)
List<String> immutable = names.toList(); // Java 16+

// → Map (key=name, value=length)
Map<String,Integer> nameLen = names.collect(
    Collectors.toMap(Function.identity(), String::length)
); // {Alice=5, Bob=3, Carol=5}

// → Joined String
String joined = names.collect(Collectors.joining(", ","[","]"));
// [Alice, Bob, Carol]
reduce()Terminal · Immutable Reduction

Reduces stream elements into a single value by repeatedly applying a BinaryOperator.

Java — reduce() — three overloads 
List<Integer> nums = List.of(1,2,3,4,5);

// 1) With identity — always returns T (no Optional needed)
int sum = nums.stream().reduce(0, Integer::sum); // 15

// 2) Without identity — returns Optional (stream may be empty)
Optional<Integer> max = nums.stream().reduce(Integer::max);
max.ifPresent(System.out::println); // 5

// 3) With combiner — type changes + parallel support
int totalLen = Stream.of("hello","world")
    .reduce(0,
        (len, s) -> len + s.length(),  // accumulator
        Integer::sum);                    // combiner (parallel merge)
// 10

// Step-by-step: reduce(0, Integer::sum) on [1,2,3,4,5]
// 0+1=1, 1+2=3, 3+3=6, 6+4=10, 10+5=15 ✅

Matching & Finding Operations — Short-Circuit

Java — Matching & Finding 
List<Integer> nums = List.of(1,2,3,4,5);

boolean hasEven = nums.stream().anyMatch(n -> n%2==0);  // true  (stops at 2)
boolean allPos  = nums.stream().allMatch(n -> n > 0);    // true  (scans all)
boolean noNeg   = nums.stream().noneMatch(n -> n < 0);   // true  (scans all)

// findFirst — first in encounter order (deterministic)
Optional<Integer> first = nums.stream().filter(n -> n>3).findFirst(); // Optional[4]

// findAny — any element (faster in parallel, non-deterministic)
Optional<Integer> any = nums.parallelStream().filter(n -> n>3).findAny();

long   count = nums.stream().count();                                  // 5
Optional<Integer> min = nums.stream().min(Comparator.naturalOrder()); // 1
Optional<Integer> max2= nums.stream().max(Comparator.naturalOrder()); // 5
Operation Returns Short-circuits On empty stream
anyMatch(pred) boolean ✅ On first true false
allMatch(pred) boolean ✅ On first false true (vacuous)
noneMatch(pred) boolean ✅ On first true true
findFirst() Optional<T> ✅ Immediately Optional.empty()
findAny() Optional<T> ✅ Immediately Optional.empty()
count() long ❌ 0
min(comp) Optional<T> ❌ Optional.empty()
max(comp) Optional<T> ❌ Optional.empty()

forEach, forEachOrdered, toArray

Java 
List<String> items = List.of("A","B","C");

// forEach — order not guaranteed in parallel
items.parallelStream().forEach(System.out::println); // A,C,B possible

// forEachOrdered — maintains encounter order even in parallel
items.parallelStream().forEachOrdered(System.out::println); // always A,B,C

// toArray() — typed array
String[] arr = Stream.of("a","b","c").toArray(String[]::new);

// Primitive toArray — no boxing!
int[] ints = IntStream.rangeClosed(1,5).toArray(); // [1,2,3,4,5]
